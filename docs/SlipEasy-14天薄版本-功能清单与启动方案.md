# SlipEasy v0.1 极薄版本 — 功能清单与启动方案

> 14 天。TestFlight 内测，不上架，不收费。
> **这不是一个产品发布，是一次实验。**

---

## 〇、这 14 天要回答什么

**一个主问题：**
> 一个还在抽烟、想戒但还没戒的人，会不会在犯烟瘾的时候主动打开一个 App，
> 完成一次 3 分钟的练习，并且在两周后还在这么做？

**三个子问题：**

| # | 问题 | 怎么测 |
|---|---|---|
| Q1 | 犯烟瘾时会不会想起来打开 App？（**这是生死问题**） | 无推送条件下的自然打开次数 |
| Q2 | 不归零的计数器，在真正复吸之后是不是还有意义？ | 复吸后 24 小时内是否还有下一次记录 |
| Q3 | "还没戒的人"是不是真的没被服务？ | 招募时刻意区分两组，比较留存 |

**明确不验证的（别混进来）：**
付费意愿、界面美观度、多工具偏好、云同步、增长渠道。

---

## 一、功能清单

**总原则：4 个屏幕，零推送，零账号，零同步，零付费。**

### 屏幕 1 — Onboarding（3 页）

| 页 | 内容 | 验收标准 |
|---|---|---|
| 1 | 一句话说明：「别的 App 从你戒烟那天开始。这个从你还在抽的时候开始。」 | 单屏，一个"继续"按钮 |
| 2 | **分流问题**：「你现在的状态是？」<br>A. 我已经戒了，在防复吸<br>B. **我还在抽，想戒**<br>C. **我还在抽，想先少抽点** | 三个选项**视觉权重完全相同**。B/C 不能看起来像"次要选项"——这是整个假设的核心 |
| 3 | 「你每天大概抽几根？」滑杆 1–40 | 存本地，仅用于后续分析 |

> ⚠️ **不要**问戒烟日期。**不要**问动机。**不要**做心理测评。3 页封顶。

### 屏幕 2 — 主页

```
┌──────────────────────┐
│                      │
│         47           │  ← 巨大数字，屏幕视觉重心
│    cravings beaten   │
│                      │
│  ┌────────────────┐  │
│  │  I want to     │  │  ← 唯一的主按钮
│  │  smoke  🔥     │  │     全宽，拇指可达区
│  └────────────────┘  │
│                      │
│  Last 7 days ▁▃▅▂▆▃█ │  ← 极简，7 根柱子，不可点
│                      │
│  [ I smoked ]        │  ← 次要按钮，低对比度但不隐藏
└──────────────────────┘
```

**验收标准**
- 冷启动到主按钮可点 **< 1.5 秒**
- 主按钮点击到干预页首帧 **< 300ms**
- 数字用 SF Rounded，尺寸 ≥ 72pt
- 「I smoked」不能藏起来，也不能是红色。用中性灰。

### 屏幕 3 — 干预：Urge Surfing（只做这一个）

**为什么只做 Urge Surfing 而不是 4-7-8 呼吸**：它是三个工具里唯一有直接实验证据链的（Marlatt 原始研究 + iCanQuit 的接纳机制），并且它就是本产品差异化的机制本身。呼吸法留到 v1.0。

**流程**（全程 3 分钟，深色背景，减少视觉刺激）：

| 阶段 | 时长 | 引导语（英文原文，直接用） |
|---|---|---|
| 1. 定位 | 20s | "Where do you feel it? Chest, throat, hands?" |
| 2. 描述 | 40s | "Don't fight it. Just describe it. Is it hot? Tight? Moving?" |
| 3. 观察 | 60s | "Notice if it changes. It might get stronger first. That's normal." |
| 4. 停留 | 60s | "You're having the craving. You're not smoking. Both are true right now." |

**结束页文案（最关键的一处，逐字照用）**

```
The craving may still be here.
That's okay — it's not supposed to disappear.
You just practiced having it without smoking.

        [ I didn't smoke ]      ← 计数 +1
        [ I smoked ]            ← 进入复吸屏
```

> ⚠️ **红线**：不得出现任何"烟瘾会消失/过去/被击退"的表述。见执行方案第四节。

**验收标准**
- 可随时退出，退出不算失败，不弹确认框
- 无音频依赖（很多人在办公室/公共场合用）
- 计时器在锁屏/切后台后继续正确计时

### 屏幕 4 — 日志（10 秒完成）

干预结束后或点「I smoked」后进入。**全部一屏，一次性提交。**

| 字段 | 交互 | 备选项 |
|---|---|---|
| 时间 | 自动 | — |
| 触发 | 单选 chip，一点即选 | Coffee / Meal / Stress / Alcohol / Break / Boredom / Other |
| 强度 | 5 格滑块 | 1–5 |
| 结果 | 已由上一屏决定 | 战胜 / 抽了 |

**复吸确认屏（必做，不是可选）**

```
Logged.

    Your 47 wins are still 47.
    They don't reset. Ever.

    [ Back ]
```

**验收标准**
- 从进入日志到提交完成 **≤ 10 秒**（自己掐表测 10 遍）
- 所有字段可跳过，跳过也能提交
- **不出现**「失败」「复发」「重新开始」「坚持」任何一个词

## 二、明确不做的清单

写下来是为了防止自己手痒。以下任何一项都会让 14 天变成 6 周：

| 不做 | 为什么 |
|---|---|
| ❌ CloudKit / iCloud 同步 | 单机 SwiftData。同步是本阶段最大的时间黑洞，且不影响任何一个验证问题 |
| ❌ 账号 / 登录 | 无 |
| ❌ 推送通知 | **故意不做。** 有推送就测不出 Q1（自然想起率），而 Q1 是生死问题 |
| ❌ 付费 / StoreKit / 付费墙 | 不验证付费意愿 |
| ❌ 呼吸法、运动、感官替代 三个工具 | 只留一个，避免"哪个工具好"污染主问题 |
| ❌ 周报 / 图表 / 热力图 | 7 根柱子够了 |
| ❌ Widget | v1.1 |
| ❌ 多语言 | 只做英文 |
| ❌ 深色模式单独适配 | 全用 `Color.primary` / `.secondary` / `.background` 系统色，深色模式自动生效 |
| ❌ iPad 适配 | iPhone only |
| ❌ 自定义设计系统 | 用 SF Symbols + 系统字体 + 一个强调色 |

## 三、埋点清单（本地记录 + TelemetryDeck）

没有数据这 14 天就白做了。**这 8 个事件，一个都不能少：**

| 事件 | 附带参数 | 回答哪个问题 |
|---|---|---|
| `onboarding_completed` | status (A/B/C), cigs_per_day | 分组依据 |
| `app_opened` | is_cold_start, hours_since_last | **Q1 核心** |
| `intervention_started` | — | Q1 |
| `intervention_completed` | duration_sec, exited_early | 3 分钟是不是太长 |
| `craving_logged` | outcome, trigger, intensity | Q2 |
| `smoked_logged` | trigger, intensity | Q2 |
| `next_log_after_smoke` | hours_gap | **Q2 核心**：复吸后还回不回来 |
| `day_n_active` | n | 留存曲线 |

**隐私**：TelemetryDeck 不收集个人身份信息。仍需在 TestFlight 说明中一句话告知："This build sends anonymous usage counts so I can tell whether the app works. No text you enter is ever sent."

## 四、14 天日程

**代码工时约 18 小时**，其余是招募、访谈、等待。别把日历填满写代码。

### 第 1 周

| 日 | 代码（约 2h/天） | 非代码（更重要） |
|---|---|---|
| D1 | 建项目、装 CLAUDE.md、定 SwiftData 模型 | **发出招募帖/私信，这件事最先做** |
| D2 | 主页 + 计数器 | 找到并联系 3 个愿意先聊 30 分钟的吸烟者 |
| D3 | Urge Surfing 全流程 | 访谈 1–2 人，重点问"上次想抽烟时你做了什么" |
| D4 | 日志 + 复吸屏 | 访谈 3 人 |
| D5 | Onboarding 3 页 | 根据访谈调整引导语措辞 |
| D6 | 埋点 + TelemetryDeck | 准备 TestFlight 说明文案 |
| D7 | 自测：10 次完整流程掐表 | 招募进度盘点，目标已锁定 ≥15 人 |

### 第 2 周

| 日 | 内容 |
|---|---|
| D8 | 打 TestFlight 构建，提交 Beta App Review（外部测试组需要审核，通常 <24h，留 1–2 天缓冲） |
| D9 | 内部测试组先跑（内部测试无需审核），修阻断级 bug |
| D10 | **正式发给所有测试用户。** 每人一条个人化私信，不群发 |
| D11–D13 | **每天联系 3 个人**，问一句："昨天有没有想抽？发生了什么？"（不问 App 好不好用） |
| D14 | 拉数据，写结论 |

> ⚠️ **TestFlight 时间陷阱**：外部测试组的首个构建需要 Beta App Review。别等到 D13 才提交。

## 五、招募 20 个人（双轨）

这是全程最难的一步，也是最容易拖垮 14 天的一步。**分成两条独立的轨。**

### 轨 A：行为验证（目标 12–15 人，中文人群也可以）

**核心洞察：Q1 和 Q2 是行为问题，不是市场问题。** "犯烟瘾时会不会打开 App"这件事，中国吸烟者和美国吸烟者的答案不会有本质差异。

- 从你能直接触达的人里找：同事、朋友、朋友的朋友
- 明确告知："这是英文界面的测试版，我要看的是你会不会用，不是你觉得好不好看"
- 门槛：**必须是还在抽、且真的想戒或想少抽的人**。不要为了凑数拉不吸烟的人试用
- 优势：招募快、能当面访谈、反馈质量高

### 轨 B：市场验证（目标 5–8 人，必须是英语母语者）

这一轨验证的是 Q3 和文案是否说得通。

**渠道（按成功率排序）：**

1. **X / Twitter 公开构建**：发一条帖子说明你在做什么 + 要找什么人。真实性门槛最低，从北京做完全可行
2. **Facebook 戒烟群组**：数量多、规模大、对帖子的容忍度远高于 Reddit
3. **r/TestFlight、BetaList** 等测试版目录
4. **r/stopsmoking：先私信版主请求许可，不要直接发帖**。这个社区约 19.3 万成员，是最精准的池子，但也是最不能搞砸的池子。Reddit 的规范是 90/10，新账号零 karma 发推广会被直接判为垃圾内容。为了 5 个测试用户而烧掉这个社区，不划算

**招募文案（英文，直接用）**

```
I'm building an app for people who want to quit smoking but haven't yet.

Not another day counter. It counts cravings you got through,
and it never resets when you slip.

Looking for ~8 people who currently smoke and want to stop,
to try a very rough TestFlight build for 2 weeks.

I'm not selling anything — it's free and there's nothing to buy.
I just need to know if it actually helps. DM me.
```

**招募时必须记录每人的分组标签**（A 已戒 / B 想戒还在抽 / C 想减量），否则 Q3 无法回答。

## 六、判据：什么算通过

D14 拉数据，对照下表。**不要事后调整门槛。**

| 指标 | 通过 | 警戒 | 失败 |
|---|---|---|---|
| **Q1** D14 仍有记录的人数 | ≥ 8 / 20 | 5–7 | ≤ 4 |
| **Q1** 人均自然打开次数（14 天） | ≥ 10 | 5–9 | < 5 |
| **Q2** 复吸后 24h 内仍有下一次记录的比例 | ≥ 60% | 40–59% | < 40% |
| **Q3** B/C 组 D14 留存 ≥ A 组 | 是 | 持平 | 明显更低 |
| 干预完成率（未提前退出） | ≥ 60% | 40–59% | < 40% |

**结果对应的动作：**

- **通过** → 按修订方案进入 P1，确定 v1.0 范围，开始做 ASO 元数据
- **Q1 失败** → 机制不成立，问题是"想不起来打开"。方向调整：Widget / 快捷指令 / 锁屏优先，而不是加功能
- **Q2 失败** → 不归零计数器没有起到设想的作用。这是整个产品的基础假设，需要重新设计而不是微调
- **Q3 失败（B/C 组留存明显更低）** → "还没戒的人"这个缺口是伪需求。回到 A 组人群，但那意味着要正面对上 Smoke Free 和 Kwit，需要重新想差异化
- **干预完成率失败** → 3 分钟太长。砍到 90 秒重测，这个改动 1 小时能做完

## 七、访谈脚本（D11–D13 每天 3 人）

**不要问「你觉得这个 App 怎么样」。** 问行为，不问评价。

1. 「昨天有没有哪个时刻特别想抽？当时在干什么？」
2. 「那一刻你做了什么？」（如果没提 App，就到此为止，**不要提示**）
3. （如果用了）「打开之前，你是怎么想起来的？」
4. （如果没用）「当时手机在手边吗？」
5. 「这两周有没有哪次抽了？抽完之后你打开过 App 吗？」
6. 「如果明天这个 App 从你手机上消失了，你会有感觉吗？」

第 3 题和第 6 题是信息量最大的两题。第 6 题的沉默比任何回答都有意义。

---

## 八、这 14 天最容易犯的三个错

1. **手痒加功能。** 每加一个工具，Q 的归因就模糊一分。清单上"不做"的项，一项都别做。
2. **先写完代码再招人。** 招募是 D1 的事，不是 D8 的事。代码 18 小时能写完，找到 20 个愿意认真试两周的吸烟者要花更久。
3. **把留存低归因为"版本太糙"。** 如果一个人犯烟瘾时想不起来打开 App，那不是因为界面丑。这正是你要的答案。
