# Decrave 官网 SEO 下一阶段计划

更新时间：2026-09-30

## 当前状态

- Google Search Console 的 `decrave.net` 域名资源已验证。
- `https://decrave.net/sitemap.xml` 读取成功，Google 已发现 10 个页面。
- 首页已编入 Google 索引。
- `nicotine-withdrawal-symptoms-timeline.html` 通过实际网址抓取测试，已提交一次编入索引请求。
- Google 的索引和效果总报表仍在处理；Bing 搜索表现报表也尚未生成。
- Plausible 中的 `App Store Click` 转化目标已确认存在。

## 阶段目标

基础技术配置和首批英文指南已完成。接下来先确认页面被抓取、建立可靠的搜索数据，再依据实际查询优化现有页面并争取相关网站的自然提及；暂不按固定数量继续发布文章。

## 接下来 24–48 小时：复查收录报表

1. 等 Search Console 报表处理完成后，查看未收录页面原因和 canonical；优先处理抓取错误或错误 canonical。
2. 等 Bing 搜索表现数据生成后，查看重要页面的抓取状态；有具体问题再修改并重新检查。
3. 不重复提交刚请求过的 URL；重复提交不会提升它的抓取队列优先级。
4. 本仓库的 GitHub Pages 部署工作流会在发布 HTML 页面改动后，将对应 canonical URL 通知 IndexNow。它只通知发生变化的 HTML 页面；提交通知不保证页面会被抓取或收录。

## 接下来 4 周：用数据决定改什么

每周查看一次 Google Search Console 和 Bing Webmaster Tools：

- 按查询词和落地页看曝光、点击、点击率、平均排名及索引状态。
- 对已收录但曝光很少的页面，先确认标题、主标题、搜索意图和站内链接是否一致。
- 对有曝光但点击率偏低的页面，改写标题和摘要，让搜索结果准确回答用户的问题。
- 对已经获得点击的页面，检查 Plausible 的自然搜索落地页、`App Store Click` 事件及按钮位置；再与 App Store Connect 的 `Website` Campaign 下载数据一起看。
- 只有当搜索数据显示明确的未覆盖问题时，才新增指南；避免同一主题拆成多篇相近内容。

Search Console 衡量 Google 搜索展示和点击；Plausible 衡量访客进入官网后的行为；App Store Connect Campaign 衡量从官网进入商店后的转化。它们的数字口径不同，应看趋势与路径，不要求完全相等。

## 同步推进：获得相关网站的自然提及

- 优先联系戒烟支持、数字健康、行为习惯和独立应用领域的编辑、Newsletter 作者或资源页维护者，提供具体产品资料，请对方自行判断是否适合介绍。
- 先完成少量高质量产品资料页，再观察是否带来真实访客和有用反馈；避免批量注册低质量目录。
- 在社区先解决具体问题。只有社区规则允许时才附产品链接，并清楚说明开发者身份；不在支持社区重复发布推广帖。
- 继续维护 App Store 页面，让产品名称、无戒烟日期、烟瘾即时支持和“失手不清零”的官网表达保持一致。
